# Milestone 3 — Core Domain + PostgreSQL — Design Specification

- **Date:** 2026-08-21
- **Milestone:** M3 — Core Domain
- **Status:** Approved design (implementation not started)
- **Author/Deciders:** Prince (owner) + Claude
- **Supersedes/uses:** M2 security foundation (`AuthenticatedUser`, `AuthorizationService`, `ApiException`/`GlobalExceptionHandler`, Flyway chain V1/V2, `/api/v1` conventions).

> This spec is the source of truth for the M3 implementation plan. It resolves every "decide"
> point in the milestone brief and aligns with `CLAUDE.md`, `docs/DATABASE.md`, `docs/API.md`,
> `docs/SECURITY.md`, `docs/TESTING.md`, and `docs/ROADMAP.md`. Where those docs and this spec
> would disagree, this spec also lists the doc edits required so nothing is left contradictory.

---

## 1. Objective & scope

Introduce two **user-owned business aggregates** — **Task** and **Customer** — backed by real
PostgreSQL, so that later milestones (M5 tools, M6 agent) can invoke `TaskService` /
`CustomerService` **through** authorization and business rules, never around them.

**In scope:** JPA entities, Flyway migrations (V3/V4), repositories, service layer, DTOs,
Bean Validation, REST CRUD APIs, ownership + RBAC authorization, pagination/filtering/sorting,
transaction boundaries, DB constraints/indexes, Testcontainers-PostgreSQL integration tests,
unit/API/security tests, docs, ADRs.

**Explicitly NOT in scope (later milestones):** Spring AI, Ollama, agent orchestration, tool
registry/tool-calling, Redis/memory, guardrails, audit-event system, Prometheus/Grafana, Kafka,
frontend, external AI APIs. No `AiService`/`ChatClient`/`ToolRegistry` is introduced. The domain
must be fully usable without AI.

## 2. Confirmed decisions (authoritative)

| # | Decision | Choice |
|---|---|---|
| D1 | Ownership representation | Plain `Long ownerId` column on `Task`/`Customer` (no `@ManyToOne User`). DB FK enforces integrity + `ON DELETE CASCADE`. |
| D2 | Authorization authority | Reuse `AuthorizationService.canAccess(user, ownerId)`; domain services load-then-authorize. No second auth system. |
| D3 | Non-owned resource access | Return **404** (indistinguishable from truly-missing) to avoid existence leakage. |
| D4 | ADMIN policy | **Own-list + admin-any-by-id**: list endpoints return only the caller's own resources (USER and ADMIN alike); ADMIN may GET/PUT/DELETE any single resource by id. Admin bypasses **ownership**, never **validation**. |
| D5 | Owner assignment | Server assigns `ownerId` from the authenticated principal. Create DTOs have **no** `ownerId` field → client cannot set/spoof ownership (mass-assignment structurally impossible). Update never changes `ownerId`. |
| D6 | Task status | Plain validated enum `{TODO, IN_PROGRESS, COMPLETED, CANCELLED}`. **No state machine** in M3; lifecycle documented, not enforced. |
| D7 | Task priority | Enum `{LOW, MEDIUM, HIGH, CRITICAL}`, default `MEDIUM`. |
| D8 | Customer status | Enum `{ACTIVE, INACTIVE}`, default `ACTIVE`. |
| D9 | PUT semantics | **Full replacement** of mutable fields. No PATCH. |
| D10 | DELETE semantics | **Hard delete → 204**. Soft delete deferred (documented). |
| D11 | Customer email uniqueness | `UNIQUE(owner_id, email)` → duplicate = **409 CONFLICT**. NULL emails allowed (multiple). |
| D12 | Response DTOs | Separate **summary** (collection) and **detail** (single-resource) response DTOs. |
| D13 | Dates | `dueDate` = `LocalDate`/`DATE` (calendar due date); audit `createdAt`/`updatedAt` = `Instant`/`TIMESTAMPTZ`. |
| D14 | Primary keys | `BIGINT GENERATED BY DEFAULT AS IDENTITY` (consistency with `users`). |
| D15 | Pagination | `page` (0-based), `size` default 20 **clamped to ≤100**, `sort=field,asc\|desc` with a **whitelist** (unknown field → 400). Default sort `createdAt,desc`. |
| D16 | Filtering | Single nullable-parameter JPQL query per list (no Specification framework). Task: `status`, `priority`, `dueBefore`. Customer: `status`, `search` (case-insensitive contains on name/email). |
| D17 | Testcontainers | Real PostgreSQL ITs (`*IT`, run by `maven-failsafe`) via a shared base using `@Testcontainers(disabledWithoutDocker = true)` + `@Container` + `@DynamicPropertySource` (robust against the base `${DATABASE_URL}` placeholder; one fewer dependency than `@ServiceConnection`). H2 fast suite (`*Test`, surefire) retained for coverage; both run the same Flyway migrations. **Not claimed verified when Docker is unavailable.** Must run in Docker-capable CI. |
| D18 | Coverage gate | Activate JaCoCo `check` in `verify`: overall ≥ 75%, service/domain ≥ 80% (`TESTING.md §8`). Sensible excludes for non-business/config code. **No meaningless tests to inflate coverage.** |

bypassed by a tool talking to a repository/`EntityManager` directly.

## 4. Domain model & database schema

### 4.1 `tasks` (migration `V3__create_tasks.sql`)

| Column | Type | Constraints |
|---|---|---|
| `id` | BIGINT identity | PK |
| `owner_id` | BIGINT | NOT NULL, FK → `users(id)` `ON DELETE CASCADE` |
| `title` | VARCHAR(200) | NOT NULL |
| `description` | VARCHAR(2000) | NULL |
| `status` | VARCHAR(20) | NOT NULL DEFAULT `'TODO'`, CHECK ∈ enum |
| `priority` | VARCHAR(20) | NOT NULL DEFAULT `'MEDIUM'`, CHECK ∈ enum |
| `estimated_hours` | NUMERIC(6,2) | NULL, CHECK ≥ 0 |
| `due_date` | DATE | NULL |
| `created_at` | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP |
| `updated_at` | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP |

Indexes (each with a query reason):
- `idx_tasks_owner_id (owner_id)` — every ownership-scoped access.
- `idx_tasks_owner_created_at (owner_id, created_at)` — default list sort (`createdAt,desc`) per owner (hot path).
- `idx_tasks_owner_status (owner_id, status)` — list filter by status.
- `idx_tasks_owner_priority (owner_id, priority)` — list filter by priority.
- `idx_tasks_owner_due_date (owner_id, due_date)` — `dueBefore` filter + due-date sort.

### 4.2 `customers` (migration `V4__create_customers.sql`)

| Column | Type | Constraints |
|---|---|---|
| `id` | BIGINT identity | PK |
| `owner_id` | BIGINT | NOT NULL, FK → `users(id)` `ON DELETE CASCADE` |
| `name` | VARCHAR(150) | NOT NULL |
| `email` | VARCHAR(255) | NULL |
| `phone` | VARCHAR(30) | NULL |
| `status` | VARCHAR(20) | NOT NULL DEFAULT `'ACTIVE'`, CHECK ∈ enum |
| `created_at` | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP |
| `updated_at` | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP |

Constraints/indexes:
- `uq_customers_owner_email UNIQUE (owner_id, email)` — no duplicate email per owner (NULLs distinct in PG/H2 → multiple null emails allowed). Serves the `(owner_id, email)` lookup too.
- `idx_customers_owner_id (owner_id)` — ownership-scoped access / list.
- `idx_customers_owner_created_at (owner_id, created_at)` — default list sort (`createdAt,desc`) per owner (hot path).

### 4.3 Portability & conventions
- SQL-standard constructs only (`BIGINT GENERATED BY DEFAULT AS IDENTITY`, `TIMESTAMP WITH TIME ZONE`, `DATE`, `NUMERIC`, `VARCHAR`, `CHECK`, `UNIQUE`) → run on PostgreSQL (local/prod) and H2-in-PostgreSQL-mode (fast tests). Flyway owns schema; `ddl-auto: none`.
- `snake_case` names; Java enums mapped `@Enumerated(EnumType.STRING)`; CHECK constraints mirror the enum values for DB-level integrity.
- Timestamps set by `@PrePersist`/`@PreUpdate` (`Instant.now()`), mirroring `User`. `hibernate.jdbc.time_zone=UTC` already configured.
- Never edit V1/V2; only add V3/V4.

### 4.4 Entity notes
- No `@ManyToOne`; `ownerId` is a plain `@Column(name = "owner_id", nullable = false, updatable = false) Long ownerId`. `updatable = false` reinforces D5 (owner never reassigned).
- `equals`/`hashCode` by id (mirrors `User`).
- Protected no-arg ctor for JPA; a domain ctor taking the required fields + `ownerId`.

## 5. Authorization & ownership model

**List (`GET /tasks`, `/customers`):** query-scoped — `findAllByOwnerId(callerId, filters, pageable)`.
Own-only for both USER and ADMIN (D4). Ownership enforced in SQL; never load-all-then-filter.

**By-id (`GET/PUT/DELETE /{id}`):**
```
entity = repo.findById(id).orElseThrow(() -> NotFound(id));   // 404 if truly absent
if (!authorizationService.canAccess(user, entity.getOwnerId()))
        throw NotFound(id);                                    // 404-mask (D3) for non-owner USER
// canAccess grants admins -> admin-any-by-id (D4) falls out; validation still runs
```
- `AuthorizationService` is the single decision point (D2) — the shape `SECURITY.md §11` reserves for future tools (resolve principal → authorize → act). No change needed to `AuthorizationService`; it already exposes `canAccess`/`requireOwnershipOrAdmin` and `isAdmin`.
- **Create (D5):** `ownerId = user.userId()` server-side. `TaskCreateRequest`/`CustomerCreateRequest` have no owner field; an extra `ownerId` in the JSON body is an unknown property and ignored.
- **Update:** loads via the same by-id ownership rule, then replaces mutable fields; `ownerId` untouched.

## 6. DTOs & validation

**TaskCreateRequest** — `title` @NotBlank @Size(max 200); `description` @Size(max 2000); `status` optional (`TaskStatus`, default TODO); `priority` optional (default MEDIUM); `estimatedHours` optional `@PositiveOrZero @DecimalMax("9999.99")`; `dueDate` optional `LocalDate`.
**TaskUpdateRequest** — full-replacement semantics. `title` @NotBlank @Size(max 200); **`status` @NotNull, `priority` @NotNull** (a full PUT must state the lifecycle fields — this prevents an omitted field from silently resetting to a default); `description`/`estimatedHours`/`dueDate` optional (omitting one clears it to null). Same size/range validation as create.
**TaskResponse (detail)** — `id, ownerId, title, description, status, priority, estimatedHours, dueDate, createdAt, updatedAt`.
**TaskSummaryResponse (collection)** — `id, title, status, priority, dueDate` (light payload).

**CustomerCreateRequest** — `name` @NotBlank @Size(max 150); `email` optional `@Email @Size(max 255)`; `phone` optional `@Size(max 30)` (+ light pattern, digits/space/`+-()`); `status` optional (default ACTIVE).
**CustomerUpdateRequest** — full replacement; `name` @NotBlank @Size(max 150); **`status` @NotNull**; `email`/`phone` optional (omitting clears to null).
**CustomerResponse (detail)** — `id, ownerId, name, email, phone, status, createdAt, updatedAt`.
**CustomerSummaryResponse (collection)** — `id, name, email, status`.

Enums bind from JSON strings; invalid value → `400 VALIDATION_ERROR` (Jackson/`HttpMessageNotReadable` already mapped). All DTOs are records; validation messages follow existing style (`"title must not be blank"`).

`ownerId` is exposed in detail responses (harmless: it is the caller's own id under D4; useful for admin-any-by-id). Never exposes another user's data on list (own-only).

**PageResponse<T>** — `record PageResponse<T>(List<T> content, int page, int size, long totalElements, int totalPages, boolean first, boolean last)`. Mapped from `Page<Entity>` after DTO conversion. We never serialize `PageImpl` directly (unstable JSON; Spring warns).

## 7. Service layer

`TaskService` (mirror for `CustomerService`):
- `create(user, TaskCreateRequest) : TaskResponse` — `@Transactional`. Assign owner from principal; apply defaults; save; map; `log.info("task.created id={} owner={}", id, ownerId)`.
- `get(user, id) : TaskResponse` — `@Transactional(readOnly = true)`. Load-then-authorize (§5).
- `list(user, TaskFilter, Pageable) : PageResponse<TaskSummaryResponse>` — `@Transactional(readOnly = true)`. Own-scoped nullable-filter query.
- `update(user, id, TaskUpdateRequest) : TaskResponse` — `@Transactional`. Load-then-authorize; replace mutable fields; save; map.
- `delete(user, id) : void` — `@Transactional`. Load-then-authorize; hard delete.

`CustomerService.create/update` pre-check `existsByOwnerIdAndEmail` and also catch `DataIntegrityViolationException` → `CustomerEmailAlreadyExistsException` (race-safe, mirrors `AuthService` duplicate-email handling). Controllers stay thin (delegate only). No business logic in repositories or controllers. No transaction spans any slow call (there are none in M3).

## 8. Repositories

`TaskRepository extends JpaRepository<Task, Long>`:
- `Optional<Task> findById(Long id)` (inherited) — used by load-then-authorize.
- `@Query` list with nullable filters + `Pageable`:
  ```
  SELECT t FROM Task t WHERE t.ownerId = :ownerId
    AND (:status   IS NULL OR t.status   = :status)
    AND (:priority IS NULL OR t.priority = :priority)
    AND (:dueBefore IS NULL OR t.dueDate <= :dueBefore)
  ```
`CustomerRepository extends JpaRepository<Customer, Long>`:
- `boolean existsByOwnerIdAndEmail(Long ownerId, String email)` (duplicate pre-check).
- `@Query` list with nullable `status` + `search` (`LOWER(name) LIKE ... OR LOWER(email) LIKE ...`).

No `findAll()` without pagination anywhere. Ownership never filtered in Java.

## 9. Controllers & API contract

Base `/api/v1`. All endpoints authenticated (deny-by-default already enforced). `@AuthenticationPrincipal AuthenticatedUser` resolves the caller (as `MeController` does). Swagger `@Tag`/`@Operation`/`@ApiResponse` on each; Bearer scheme already global.

| Method | Path | Success | Notes |
|---|---|---|---|
| POST | `/api/v1/tasks` | 201 + `Location` | body `TaskResponse` |
| GET | `/api/v1/tasks` | 200 | `PageResponse<TaskSummaryResponse>`; params `page,size,sort,status,priority,dueBefore` |
| GET | `/api/v1/tasks/{id}` | 200 | `TaskResponse` |
| PUT | `/api/v1/tasks/{id}` | 200 | full replacement |
| DELETE | `/api/v1/tasks/{id}` | 204 | hard delete |
| POST | `/api/v1/customers` | 201 + `Location` | body `CustomerResponse` |
| GET | `/api/v1/customers` | 200 | `PageResponse<CustomerSummaryResponse>`; params `page,size,sort,status,search` |
| GET | `/api/v1/customers/{id}` | 200 | `CustomerResponse` |
| PUT | `/api/v1/customers/{id}` | 200 | full replacement |
| DELETE | `/api/v1/customers/{id}` | 204 | hard delete |

Status codes reuse the M1/M2 envelope and semantics (`API.md §2`): 400 `VALIDATION_ERROR`, 401 `UNAUTHORIZED`, 403 `FORBIDDEN` (RBAC), 404 `NOT_FOUND` (missing **or** non-owned), 409 `CONFLICT` (customer email), 500 `INTERNAL_ERROR`. Sort whitelist violation and out-of-range params → 400.

Sort whitelists: **tasks** `{createdAt, updatedAt, dueDate, priority, status, title}`; **customers** `{createdAt, updatedAt, name, status}`. Size clamped to `[1,100]`, default 20; page `>= 0`.

## 10. Error handling & exceptions

Reuse `GlobalExceptionHandler`, `ApiException`, `ApiError`. Add:
- `TaskNotFoundException` / `CustomerNotFoundException` → extend `ResourceNotFoundException` (404 `NOT_FOUND`).
- `CustomerEmailAlreadyExistsException` → extends `ApiException(HttpStatus.CONFLICT, "CONFLICT", …)`.

No new error-rendering plumbing; no `InvalidTaskStateTransitionException` (D6 — no state machine). No stack traces or internal detail leaked. New machine code `CONFLICT` documented in `API.md`.
