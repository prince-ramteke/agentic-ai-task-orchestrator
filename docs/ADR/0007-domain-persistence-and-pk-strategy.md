# ADR-0007: Domain Persistence & Primary-Key Strategy

- **Status:** Accepted
- **Date:** 2026-08-21
- **Deciders:** Prince

## Context

`docs/DATABASE.md` deferred the surrogate primary-key and id strategy for business tables to "an
ADR at M3". M3 adds the first business tables (`tasks`, `customers`). The existing security tables
(`users`, `roles`, `user_roles`) already use `BIGINT GENERATED BY DEFAULT AS IDENTITY`. Schema is
owned by Flyway (`ddl-auto: none`) and must run on both PostgreSQL (local/prod) and H2 in
PostgreSQL-compatibility mode (fast tests).

## Decision

- **Primary keys:** `BIGINT GENERATED BY DEFAULT AS IDENTITY` (JPA `GenerationType.IDENTITY`),
  consistent with `users`. No UUIDs.
- **Naming:** `snake_case` tables/columns; ownership FK column named `owner_id`.
- **Enums:** stored as `VARCHAR(20)` via `@Enumerated(EnumType.STRING)`, with a DB `CHECK`
  constraint mirroring the allowed values (belt-and-suspenders integrity, portable across PG/H2).
- **Timestamps:** audit `created_at`/`updated_at` as `TIMESTAMP WITH TIME ZONE` → `Instant`,
  set by `@PrePersist`/`@PreUpdate`; `hibernate.jdbc.time_zone=UTC`.
- **Dates vs timestamps:** a task's `due_date` is a calendar `DATE` → `LocalDate` (deliberately not
  an instant); audit timestamps remain instants. This split is intentional and documented.
- **Money-like value:** `estimated_hours` as `NUMERIC(6,2)` → `BigDecimal`.
- **Portability:** SQL-standard DDL only, so the same Flyway migrations run on PostgreSQL and
  H2-in-PostgreSQL-mode.

## Alternatives considered

- **UUID primary keys:** rejected — inconsistent with `users`, no M3 need for client-side/distributed
  id generation, larger indexes.
- **Native PostgreSQL `ENUM` types:** rejected — migration/portability friction; `VARCHAR + CHECK`
  is portable and equally safe.
- **`due_date` as `TIMESTAMPTZ`:** rejected — a due date is a calendar date; modelling it as an
  instant invites timezone confusion for "due on the 25th".

## Consequences

- One uniform id strategy across the schema; enum integrity enforced at the database as well as in
  the application; a clear, documented date-type split.
- A real bug surfaced and was fixed during M3 that only appears on PostgreSQL: a nullable `String`
  filter parameter must be `CAST(... AS string)` in JPQL so PostgreSQL can type the bind (H2
  tolerated the untyped null). This reinforces the value of the Testcontainers suite (ADR-0008).
