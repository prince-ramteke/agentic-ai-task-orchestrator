# ADR-0005: Database migration and test-database strategy

- **Status:** Accepted
- **Date:** 2026-08-21
- **Deciders:** Prince Ramteke
- **Milestone:** M2 — Authentication & Authorization

## Context
M2 introduces persistence. A production-style project must own its schema through versioned migrations (never auto-DDL) and must test that schema and the JPA mappings reproducibly — ideally without depending on a developer's locally-installed database.

## Decision
- **Flyway** owns the schema. All changes are versioned, forward-only migrations in `classpath:db/migration` (`V1__…`, `V2__…`). Applied migrations are never edited.
- **`spring.jpa.hibernate.ddl-auto: none`** — Hibernate never generates or mutates DDL. Flyway is the single source of truth; entity/schema drift is caught by the repository and integration tests that run real SQL.
- **Portable SQL:** migrations use SQL-standard constructs (`BIGINT GENERATED BY DEFAULT AS IDENTITY`, `TIMESTAMP WITH TIME ZONE`, standard constraints) that run on **both** PostgreSQL and H2.
- **Tests run against H2 in PostgreSQL-compatibility mode** (`MODE=PostgreSQL`), executing the **same** Flyway migrations. This makes the security suite reproducible in any environment — including CI and this build environment, where no Docker daemon or local PostgreSQL is available.
- **Testcontainers-PostgreSQL integration tests are deferred to M3**, when the domain persistence layer grows and a Docker-backed, gated `*IT` suite earns its keep.

## Alternatives considered
- **Testcontainers PostgreSQL now:** the most production-faithful option and the long-term target, but it requires a running Docker daemon, which is unavailable in the current build environment — tests could not be *verified* here, violating the "evidence before assertions" rule. H2 with identical migrations gives reproducible verification now; Testcontainers arrives in M3.
- **`ddl-auto: validate`:** a useful safety net, but H2-vs-PostgreSQL type reporting differs enough to cause spurious validation failures; the integration tests (real SQL against the real schema) already catch drift. Reconsider once tests run on Testcontainers-PostgreSQL (M3).
- **Hibernate auto-DDL (`create`/`update`):** rejected for a production-style project — non-reproducible and unsafe.

## Consequences
- The security schema is reproducible and migration-tested without external infrastructure.
- Migrations must stay portable until M3; any PostgreSQL-only feature needed before then requires revisiting the test-DB choice (or moving that test to Testcontainers early).
- A benign Flyway warning ("H2 2.3.232 newer than tested") appears in test logs; migrations apply correctly.
